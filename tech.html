System Architecture

Engineered for Deterministic Reliability

ARGUS avoids single-point failures by decoupling high-level computer vision and web telemetry from the physical motor control and safety watchdog.

Tier 1: High-Level Brain (Raspberry Pi 5)

Linux OS

Equipped with a quad-core 64-bit Arm Cortex-A76 processor running at 2.4GHz. The RPi 5 handles camera video pipeline ingestion, running YOLO edge inference models for obstacle and hazardous container tagging, and serving low-latency web streams over HTTP/WebSocket.

  • • Optical Input: Pi Camera 3 (Sony IMX708, HDR)
  • • AI Pipeline: YOLOv8 Quantized Onnx / TFLite
  • • Gas Interface: I2C connection to ADS1115 ADC

Tier 2: Real-Time Core (ESP32 MCU)

Bare-Metal Firmware

Dedicated dual-core 240MHz microcontroller with hardware timers. The ESP32 is completely insulated from Linux OS scheduling latency. It executes high-frequency PWM signal generation directly into the TB6612FNG motor driver and enforces hardware failsafes.

  • • Motor Driver: TB6612FNG Dual H-Bridge (1.2A continuous / 3.2A peak)
  • • Watchdog Timer: 500ms heartbeat counter with auto-kill
  • • Auxiliary Stream: Secondary ESP32-CAM standalone feed

Safety Protocol

The 500ms Fail-Safe Watchdog

In industrial environments, wireless signals can easily suffer multipath reflections, packet loss, or radio dead-zones caused by thick concrete walls and metal shelving.

Rather than buffering the last driving command and risking a runaway collision into a hazardous container, the ESP32 maintains an internal millisecond counter. If a fresh command packet is not acknowledged within 500 ms, the firmware immediately sets all motor enable pins low and shorts the motor windings for dynamic braking.

Watchdog Pseudocode
void loop() {
  if (millis() - lastPacketTime > 500) {
    // 500ms signal timeout tripped!
    brakeAllMotors();
    failsafeStatus = FAILSAFE_ACTIVE;
  } else if (gasPpm >= GAS_THRESHOLD) {
    // Dangerous gas threshold tripped!
    inhibitForwardDrive();
  }
}
